The result's effect reads the field back: readback is what the field shows now (hidden for password fields) and readbackMatches whether it is the intended text; text that did not land is retried once automatically. effect.kind is done, small_change, no_effect or place_changed as for other actions. On a screen the element list cannot read (an app that draws its own screen), give the input box's point instead of a ref: x+y (a visibleText center) or the @vN ref from phone_find_visually. The point is tapped and the text pasted into the box there, keyboard showing or not, then checked against the screen text: verification match means it went in; point_not_typed means that point did not take the text, so find the box again instead of repeating it. Without a ref or point, the text goes into whichever box holds focus the same way; no_focus means give the box's point.
