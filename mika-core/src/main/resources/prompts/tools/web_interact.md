Mouse and keyboard actions on the web page that web_tap and web_type_text cannot do. hover: move the mouse onto an element (ref+snapshotId) or point (x,y) to open hover menus and tooltips. drag: press at the element or point, move in steps and release over toRef (same snapshotId) or toX,toY (sliders, drag-to-sort, drag and drop). select: pick an option of a native drop-down (role combobox from a <select>) by its shown text or value. key: press a key or combination on the focused element, e.g. Escape, Shift+Tab, Control+A, ArrowDown. dialog: answer the dialog the page opened (alert, confirm, prompt or leave-page check, shown as dialog in the screen read): answer accept or dismiss, and text for a prompt. While a dialog is open the page is paused and every other action fails with dialog_open; it stays open until you answer it. hover, drag and select fail with devtools_unavailable when this tab has no DevTools connection; then use web_tap instead. The result's effect says what the action did to the interface: done (a clear change), small_change (only focus, a toggle or one or two elements changed, or it may still be loading: check it), no_effect (nothing in the interface changed: try another way instead of repeating) or place_changed (now somewhere else, given in effect.to).
