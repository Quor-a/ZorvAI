Hand the screen to the user for a step only they can do (signing in, a verification puzzle, a payment or another step the tools cannot complete). Say in message exactly what they need to do. Getting control back does not prove the step worked. With outcome complete, read the screen first and check the result (for a payment, the order status; for a sign-in, that you are signed in). If it checks out, go on or report. If you cannot tell, call ask_user with options such as "Done" / "Not done, let me take over again" / "Stop" (in the user's language). Check even when inputCount is 0, since the user may have done it some other way; only when you see no sign of it, treat the step as not started and ask whether to hand over again. Never go by durationMs, and never say a step succeeded without checking. Outcome skipped or timeout means nothing was handed back: do not claim the user handled it; say what happened, then try another way or end the task. Once the user hands back, continue the task.
