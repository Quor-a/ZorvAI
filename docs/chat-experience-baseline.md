# 对话体验基线（参考版本 1.0.172）

本文是 QuroAI 对话与 Agent 体验的对标基线：把参考实现的功能面、对话细节逐项摊开，与当前仓库逐条核对，标出差距与落点。

- 参考版本：1.0.172（Android，minSdk 26 / targetSdk 36）
- 核对范围：`app/src/main/java/com/ai/assistance/quro/**`
- 结论以「✅ 已有 / △ 部分 / ❌ 缺失」标注，缺失项在第四节排优先级，第五节给落点。

---

## 摘要：五条主线

1. **Bot 是一等公民。** 参考实现里所有对话都挂在某个 Bot 上；模型、提示词、工具开关、Skills、MCP、Soul、Memory、音色、桌宠、主动模式、进化频率、IM 接入全部按 Bot 隔离。我们是「全局配置 + 人格」，人格只承载语气，不承载工具与运行策略。
2. **「进行中」要说到具体动作。** 参考实现的等待态不是一句「思考中」，而是可枚举的活动流：正在搜索网页 / 读取文件 / 编辑文件 / 运行命令 / 操作手机 / 读写记忆 / 管理日程 / 调用智能体，并且能并列显示「3 项任务」。
3. **工具调用的可读性决定信任。** 参数与结果之上加一层人话摘要（点击「设置」、拖拽 A 到 B、输入 12 个字符），危险操作走结构化审批卡，产出走成果卡。
4. **上下文要可观测、可干预。** 上下文窗口按来源拆开显示占用，压缩可手动触发也可中途停止，压缩成功的位点留一条「以上内容已压缩」的分隔线。
5. **输入要能竞争。** 回复进行中再发消息，参考实现给两个明确语义：排队（等本轮结束）与引导（插入当前轮，AI 下次调工具时读到并据此调整）。

## 四、差距清单与优先级

### P0 — 直接影响「对话是否可信」

1. **轮次失败归因**（8 类）。当前所有异常都收敛成「生成失败」，用户无法判断是模型还是工具。
2. **上下文窗口构成明细**。有 token 数据但不展示，用户不知道为什么会忘事。
3. **工具摘要层**（`tool_display`）。原始 JSON 参数无法扫读。
4. **活动流三态 + 动画词映射表**。已在做的方向，补齐并列与通用映射。
5. **消息操作补全**：修改、删除、朗读、从此消息创建分支。

### P1 — 决定「用起来顺不顺」

6. 回复中再发：排队 / 引导。
7. 临时对话。
8. 上下文压缩升级为可停止的摘要压缩 + 压缩位点分隔线。
9. 审批卡（结构化事实 + 三档允许 + 防注入提示）。
10. 提问卡状态机补全（已回答/已结束/跳过）。
11. 侧栏时间分组细化 + 聊天内搜索 + 多选批量。
12. 语音条（合成语音消息 + 转文字 + 听筒切换）。
13. 每消息用量（用时/输入/输出/缓存命中）。

### P2 — 体系化

14. Bot 一等公民（Persona 扩展为 Bot：模型/工具/Skills/MCP/Soul/Memory/音色），Bot 包导入导出。
15. 目标模式。
16. 主动模式 + open_items。
17. 统计看板。
18. 桌宠。
19. Bot 互问。
20. Telegram 桥接。

## 五、实现落点

> 原则：只加数据字段与渲染分支，不改现有链路语义；新能力一律默认关闭，避免影响既有对话。

| # | 落点 | 做法 |
|---|---|---|
| 1 | `core/network/QuroLlmClient.kt`（已有 `readMeta`）→ 新增 `core/chat/TurnOutcome.kt` | 把 finish_reason / 空正文 / 工具后无回复 / 长度上限 等收敛成密封类，`QuroChatViewModel` 与 `ChatScreen` 按类型出文案 |
| 2 | `ui/data/ChatData.kt` 的 `Message` 增加 `usage: UsageInfo?`；`core/QuroAssistant.kt` 填充 | 菜单里显示用时/输入/输出/缓存命中 |

| 4 | 新增 `core/tools/ToolDisplay.kt`（纯函数，可单测） | 按工具名 + 参数 → 一句中文摘要；`ToolCallRichCard` 只负责渲染 |
| 5 | `ui/data/ChatData.kt` 增加 `MessageActivity`（Thinking / Tool / Writing） | `ChatScreen` 的活动区改为并列 chip |
| 6 | `Composer` 增加 `pendingSendMode: Queue / Steer` | Steer 时把文本注入当前轮的工具结果尾部 |

| 8 | `core/QuroAssistant.compactForLocal` 旁新增 `ContextCompactor` | 可停止、内容指纹校验、结果插一条分隔消息 |
| 9 | 新增 `core/tools/approval/ApprovalRequest.kt` + `ui/chat/ApprovalCard.kt` | 事实块 + 参数预览 + 三档允许 + 「以实际调用为准」 |
| 10 | `VisualQuestionTool` 补状态机 | 已回答/已结束/跳过三态持久化 |
| 11 | `ChatData.HistoryItem` 增加 `timeBucket` | 已置顶/今天/昨天/7 天/30 天/更早 |
