终端 3.0 技术构架

ZorvAI · 前代原生终端栈（VT 模拟器 + proot ubuntu-base）

一、构架介绍

终端 3.0 是 ZorvAI 在引入 terminal-core（OperitTerminal v1.2 移植，即终端 4.0）之前的原生终端实现。它在 UI 侧复用 Termux 式 VT 终端模拟器（QuroTerminalPane / QuroTerminalInputView），环境侧依赖「ubuntu-base 微镜像 + 运行时 apt-get 下载」的 proot 方案，并通过 QuroTerminalController / QuroTerminalBridge 打通 AI 的 terminal_exec。

该方案「能用但脆弱」：首启需联网从 apt 源下载补全工具链，受源可用性、网络、架构兼容影响，易失败、启动慢。这正是终端 4.0 用「完整 rootfs 作为 assets 打包进 APK、开箱即用」取代它的根本原因。

设计要点：

  • VT 渲染：基于 QuroTerminalPane 的终端模拟器，承接键盘/鼠标/快照，渲染真终端流。
  • proot + ubuntu-base：QuroLinuxEnv 负责确保 proot 与基础 Ubuntu 环境可用，必要时 apt install 工具链。
  • AI 直连：QuroTerminalBridge / QuroToolsTerminal 把 AI 指令派发到同一终端管线。
  • 保活与权限：QuroTerminalKeepAliveService + QuroTerminalPrivilegeBridge 保障常驻与特权操作。

四、关键流程

4.1 首启环境准备（脆弱点）

1QuroLinuxEnv 检查 proot 与 ubuntu-base 是否已就绪
2缺失则联网 apt-get 下载 / 安装基础包与工具链（受源与网络影响，易失败）
3就绪后拉起 proot shell，经 pty 回显到 VT

4.2 命令执行（用户 / AI 通用）

1VT 输入 或 AI terminal_exec → QuroTerminalBridge
2QuroTerminalController 经 QuroTerminalSessionManager 取会话
3proot shell 执行，输出经 VT 模拟器渲染 / 回传 AI

五、与终端 4.0 的关系

终端 3.0 是终端 4.0 的前身，二者共存于 ZorvAI：

终端3.0：ubuntu-base + apt（联网脆弱） 终端4.0：完整 rootfs 打包 assets（开箱即用）

演进路径：QuroLinuxEnv 的 apt 方案被 terminal-core 的 TerminalManager（rootfs 解压）取代；VT 渲染（QuroTerminalPane）与 AI 接入（QuroTerminalBridge）作为成熟层被保留，UI 侧另叠加终端 4.0 的 Compose TerminalScreen。保活 / 特权桥 / AI 工具等控制面在两条栈上复用。
