MCP 介绍构架

Model Context Protocol · 连接器 / 工具扩展

一、构架介绍

MCP（Model Context Protocol，模型上下文协议）是一套开放标准，让 AI 应用以统一方式接入外部工具、资源与数据源。WorkBuddy / ZorvAI 通过 MCP 服务器把「第三方能力」变成 Agent 可调用的工具（mcp__<server>__<tool>），而无需把每种集成写死进代码。

在 ZorvAI 体系中，MCP 与「连接器（Connector）」一体两面：连接器是面向用户的托管入口，MCP 是背后的协议实现。两者共同扩展了主理人的行动半径（浏览器、飞书、Git、云盘、数据库……）。

  • 配置即接入：所有服务器集中于 ~/.workbuddy/mcp.json 的 mcpServers 字段，按官方文档填 command/args/env 或 url。
  • 信任即启用：写入配置后服务器不会自动激活，须到连接器管理页面对新服务器点「信任」才生效——这是一道安全闸门。
  • 三种传输：stdio（本地进程，如 npx @playwright/mcp）、SSE / Streamable HTTP（远程服务）。

三、核心组件

组件职责说明
mcp.json服务器注册表路径 ~/.workbuddy/mcp.json（注意无 dot 前缀）；合并写入，保留其它服务器
MCP Client协议实现 / 工具路由自动把远程工具映射为 mcp__server__tool
连接器管理信任与启用新服务器写入后须手动「信任」激活
Tools / Resources / Prompts三类能力面工具可调用、资源可读取、提示可模板化

四、接入流程

1查文档：先读目标提供方官方 MCP 文档，取准确 command/args/env/url，不臆测字段
2读配置：若 ~/.workbuddy/mcp.json 已存在则合并，不覆盖其它服务器
3写配置：以官方格式写入 mcpServers（stdio 用 npx；远程用 url）
4信任：到连接器管理页面对新服务器点「信任」启用（写入不会自动激活）
5调用：Agent Loop 经 tools/list 发现、tools/call 执行远程能力

五、典型服务器示例

已接入 / 可接入的代表：

Playwright (浏览器自动化) 飞书 Lark (IM/文档/多维表格/日历) GitHub (gh CLI) 云盘 / 空间 数据库 / 搜索引擎 自定义 stdio 工具

注：凡涉及凭据（token / API key）的服务器，凭据写入官方文档指定的位置（env / headers / args）；缺失则向用户索取，不外泄。
