终端 4.0 技术构架

ZorvAI · 模块：terminal-core

一、构架介绍

终端 4.0 是 ZorvAI 内置的「开箱即用」Linux 终端引擎，目标是让用户无需任何下载 / apt 安装即可在 Android 上获得完整 Ubuntu 环境（apt、python3、node、git 等一应俱全），同时无缝对接 AI 工具调用与保活服务。

它直接继承并去品牌化移植自 OperitTerminal v1.2：把 64MB 完整 Ubuntu rootfs 作为 assets 打包进 APK，TerminalManager.extractAssets() 直接从 context.assets.open 解压，首启即拥有完整发行版，彻底取代旧方案「ubuntu-base 微镜像 + 运行时 apt-get 下载」的脆弱链路。

核心设计原则：

  • Native 软链而非拷贝：proot / loader / bash / busybox / sudo 五个预编译 .so 经 Java NIO Files.createSymbolicLink 软链进 binDir，零冗余体积、启动即就绪。
  • Provider 抽象：本地 proot Ubuntu 与远程 SSH 终端统一在 TerminalProvider 接口之后，UI / AI 不感知底层差异。
  • AI 双向接入：AI 的 terminal_exec / terminal_write 与用户在对话框内手敲命令走同一条 TerminalManager → LocalTerminalProvider → Pty 管线。
  • 会话可多开：SessionManager 管理多标签会话，Pty（JNI）持有真 pty 文件描述符，输出经 ANSI 模拟器渲染。

四、关键流程

4.1 首启环境初始化

1TerminalManager.initializeEnvironment() → createDirectories() 建 usrDir / binDir / tmp
2linkNativeLibs()：busybox + proot/loader/bash/sudo 从 .so 软链进 binDir 并 setExecutable
3extractAssets()：仅当不存在时解压 ubuntu-noble-aarch64-pd-v4.18.0.tar.xz（64MB）与 setup_fake_sysdata.sh
4generateStartScript() 写出 common.sh（含 install_ubuntu()、resolve_proot_runtime() 自动探测 --link2symlink）
5首条命令触发 install_ubuntu()：rootfs 解压到 var/lib/proot-distro/installed-rootfs/ubuntu，写 .operit_installed_ok 标记

4.2 一次命令执行（用户 / AI 通用）

1UI 输入 或 AI terminal_exec → QuroTerminalBridge
2SessionManager 取当前 TerminalSession → LocalTerminalProvider.startSession()
3proot 进程执行 common.sh login_ubuntu，经 pty 回显
4OutputProcessor + AnsiTerminalEmulator 渲染到 TerminalScreen / 回传 AI

五、移植状态与缺口

当前 terminal-core 已落地 40 个 Kotlin 文件（全部去品牌化至 com.ai.assistance.quro.terminal），app 已 implementation(project(":terminal-core"))，ChatScreen 直接复用 Operit 原生 TerminalScreen。

相对 OperitTerminal v1.2 完整仓库，仍存在 Provider 抽象层（TerminalProvider / Local / SSH） FileSystemProvider 体系 UbuntuDocumentsProvider SSH 全栈（config/screen/manager） 设置 / 虚拟键盘自定义 等缺口，列为终端 4.0 后续迭代项。
