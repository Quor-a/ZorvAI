# 退役插件与当前注入清单一致

当前 APK 的构建参数和权威 patch 已不注入或挂载 undo-savepoint，成员完整性门禁却仍从 externals 要求它在 web/headless 包内，完整链因而误报缺包。

externals 现只列当前包，retiredExternals 保留历史源码路径。源码和旧用户快照均不删除。协调仓同步 APK 已有的退役构建参数和挂载配置，避免另一条链重新挂载旧入口。

成员检查逻辑不放宽。--self-test 四项验证历史源码可保留、当前包仍必须在两个 profile 完整存在；缺活动包与缺相对依赖文件两条负控都拒绝归档。最终双 ABI 构建和覆盖安装证据随后登记，未做设备验证（指最终候选三层尚未完成）。

完整链同时复现 Windows 单一注入源的数组展开问题：@(@(...)) 在只剩一个根级包时被 PowerShell 展平成两个字符串，降级步骤读到字符而非源目录，最终包携带未降级语法。现用一元逗号保留二元数组，自检实际执行构建脚本中的循环表达式；旧表达式负控仍能复现错误配对。新增两项通过，共六项自检。

实际双 ABI 全链还发现鉴权产物检查强制要求已退役 undo 文件。现仅在清单明确退役且实际 profile 无挂载引用时允许缺席；历史文件若仍在包内，仍检查它自己的鉴权标记。归档单次流式读取固定成员，不落盘，不再拼接不同文件的输出。六项真实函数回归涵盖重新挂载、活动包缺席、跨文件标记冒充及重复/链接成员拒绝。
