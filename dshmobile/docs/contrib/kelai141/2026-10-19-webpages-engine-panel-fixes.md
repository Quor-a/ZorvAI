# 下载页改版修掉的两个真因（2026-10-19）

主题：`webpages` 下载页「引擎面板」改版（PR #448）过程中修掉的两处缺陷。
共同根因：**同一份事实在模板、构建脚本、样式表各写一份，缺一处校验就静默失效**——
页面照常渲染、构建照常退出码 0，坏的是没人守的那一处。

## 1. 新增占位符漏进替换表：字面量 `__TAG__` 直发线上

- **现象**：下载面板 `release` 参数行显示字面量 `__TAG__`，而同面板的版本徽标显示 `v0.14.7`，
  两处不一致；页面其余部分完全正常，构建与门禁全绿。
- **真因**：模板新增 `__TAG__`，但 `tools/build.mjs` 的 `render()` 替换表只有
  `__STYLES__` / `__RELEASE_DATA__` / `__JSONLD__`，`assertRendered()` 的守卫清单也是同样三项。
  `.replace()` 不匹配时原样保留，而守卫只检查它自己那份清单——**替换表与守卫清单同源，
  于是二者会一起漏**，构建期占位符是纯字符串替换，没有任何机制保证「模板出现的 token 都被替换」。
- **修法**：`render()` 增加 `.replace('__TAG__', () => data.tag)`，`assertRendered()` 清单同步补
  `__TAG__`；并在 `tests/release-delivery.test.mjs` 的构建回环里对**产物**加断言
  `doesNotMatch(/__[A-Z][A-Z0-9_]*__/)` —— 不依赖替换表怎么实现，任何漏替换的 token 都会判红。
- **复验证据**：先只加断言、不改构建脚本，`node --test webpages/tests/release-delivery.test.mjs`
  判红（`构建产物里残留未替换的占位符`），受控负控成立；补上替换后门禁 39 项全绿，
  产物 `grep -c "__[A-Z]"` = 0，`release` 行实测为 `v0.14.7`。

## 2. 状态伪类特异性压过选中态，把按钮文字染成与底色同色

- **现象**：点一下线路按钮把它选中，鼠标仍停在钮上时该按钮标签文字消失
  （浅色模式下钮是深底、文字也变深）；鼠标移开即恢复。用户报的形态是
  「点了之后文字先会黑，再点一下旁边才正常」。
- **真因**：`.lines button:hover:not(:disabled)` 特异性 (0,3,1) 高于
  `.lines button[aria-pressed="true"]` (0,2,1)，于是悬浮「已选中」的线路按钮时 `color`
  被改成 `var(--text)`，而它的 `background` 是 `var(--fill)`；在两套令牌里
  **`--text` 与 `--fill` 取值完全相同**（浅色同为 `#1d1d1f`，暗色同为 `#f5f5f7`），同色即不可见。
  光调声明顺序无用——只在特异性更高的规则里排除选中态才治得住。
  另注：主下载按钮 `#dl-main` 全状态恒为白字深底，实测与本缺陷无关，别改错对象。
- **修法**：悬浮规则改为 `.lines button:not([aria-pressed="true"]):hover:not(:disabled)`，
  显式把选中态排除在悬浮变色之外；行内注释写明「`--text` 与 `--fill` 同值」这一前提。
- **复验证据**：浏览器实测（浅色方案）选中钮非悬浮时 `color=rgb(255,255,255)` /
  `bg=rgb(29,29,31)`；`browser_hover` 确认 `:hover` 命中后两者不变且不相等
  （修复前实测 `color == bg == rgb(29,29,31)`）；点击后指针仍在钮上时文字仍可读，
  截图 `hovered-viewport.png` 佐证。

## 可复用结论

- 「模板里出现的占位符必须被替换」不能靠人记：替换表与守卫清单同源、会一起漏，
  唯一可靠判据是对**构建产物**断言「不含任何占位符残留」。
- 「`--text` 与 `--fill` 同值」是本项目明暗两套令牌的固有前提：任何给
  `background: var(--fill)` 的元素配 `color: var(--text)` 的状态规则都会造成同色不可见。
  写状态规则前先问一句「这个元素有没有反色底」。
