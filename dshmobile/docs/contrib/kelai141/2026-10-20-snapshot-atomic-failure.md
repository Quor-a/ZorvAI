# 快照配置原子发布失败时保留旧文件

快照合并的 `writeTextAtomic` 在 `renameTo` 失败后回退到 `target.writeText`。这会先截断旧 `package.json` 或 `cordis.patch.yml`，磁盘满或中断时可能留下半份用户配置。

现在先校验待写内容，写入同目录唯一临时文件并同步，再执行替换。替换失败直接中止，不能打开旧目标进行截断写入。失败留证采用独立名称复制旧字节；留证失败不掩盖发布失败的根因。

JVM 故障注入覆盖发布返回 false 后旧目标逐字节不变、临时文件清理、完整成功发布，以及非法 JSON 在写前被拒。受控失败由实际发布函数返回 false 注入，新实现必须报错并保留旧目标；不以另写一份旧算法代替真实代码测试。设备层需以本候选打包后的三层验收为准；未完成前不得合并发布。
