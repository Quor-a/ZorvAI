# 手机操作

## 循环：观察 → 决策 → 执行 → 再观察

**没有最新截图就不许给坐标。**
基于上一步的截图推断这一步的位置，是最常见的错误来源（页面会滚、会跳转、会异步加载）。

```
截图 → 找到目标元素 → 给出坐标 → 执行 → 重新截图 → 判断是否达成 → 未达成则改策略
```

## 禁止的操作

- ❌ **不凭记忆给坐标**。坐标必须来自本次执行的截图。
- ❌ **不连续盲点**。点完必须重新观察。
- ❌ **不跳过危险动作确认**。以下必须先说明后果并等用户确认：
  - 付款 / 下单 / 转账
  - 删除数据 / 清空 / 卸载
  - 对外发送消息（发给别人、群发、评论）
  - 授权 / 开启权限 / 登录
- ❌ **不代替用户做判断题**。验证码、选择题、协议勾选 → 交回用户。
- ❌ **不在验证码/支付密码等界面尝试自动填写**。

## 执行前必须说清三件事

1. **我现在看到什么**（截图里的实际内容，不是猜测）
2. **我要点什么**（目标元素 + 坐标）
3. **点了会发生什么**（副作用）

## 定位失败怎么办

点了没反应、页面没变化，**不许换个坐标继续盲试**：

1. 重新截图，确认页面是否真的没变。
2. 没变 → 检查是否需要先滑动、是否有遮挡层、是否需要等加载。
3. 滑动了再找 → 重新截图定位。
4. 连续两次点不动 → 停止，如实告诉用户「点不动，页面在此处没有响应」，**不许硬试第三次**。

## 元素找不到时

- 先滚一屏再找（一次一屏，不许连续猛滑）。
- 找不到就报告「这一屏没找到 X，可能需要下翻」，**不许猜一个相似元素点上去**。
- 判断依据不足时宁可不动作。点错一次的代价通常大于少做一步。

## 滑动的规矩

- 滑动前确认当前是否在列表中间（决定往上还是往下找）。
- 滑一次 → 重新截图 → 再判断。**不许连续滑多次不看**。
- 到顶/到底会明显减速或回弹，据此判断还有没有内容。

## 自检清单

- [ ] 坐标来自**本次执行**的截图，不是上一步的
- [ ] 执行前说清了：看到什么 / 点哪里 / 点了会发生什么
- [ ] 危险动作（付款/删除/发送/授权）已确认过
- [ ] 验证码、选择题已交回用户，未自动填写
- [ ] 点完已重新观察，未连续盲点
- [ ] 点不动时已停止并如实报告，未硬试第三次
- [ ] 找不到元素时已报告，未猜测相似元素
- [ ] 滑动一次一观察，未连续盲滑

## 交付时说清

做了哪几步、每步观察到什么、有没有卡住及卡在哪。
**部分完成时必须明说停在哪一步、当前页面状态是什么**，不许说「完成了」然后停在半路。
