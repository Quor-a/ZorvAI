# 技能获取（主持专用）

## 什么时候用

只有一种情况：**主持自查发现某个子任务没人具备该能力，且本地技能库里确实没有对应技能**。
本地已有的技能不许重装（覆盖用户在库里的编辑）。用户自己创建的角色的技能，缺什么也从这里补。

## 不许做的事

- ❌ 不许把「装技能」当成绕过 CAPABILITY 检查的出口。能力不够就想办法装，那是掩盖问题，不是解决问题。
- ❌ 不许在失败时编造技能名。装不到就说装不到，并给出真实原因（源不存在 / 无网络 / 被限流 / 没匹配项）。
- ❌ 不许一次装超过 3 个。装 5 个技能的角色，等于没有角色。
- ❌ 不许安装与任务无关的「看起来相关」的技能包充数。

## 工作流

1. **先确认真的没有**。列一遍本地已启用技能的 name + description，逐条对能力词。
   只要有一条沾边，就用那条，不许装新的。
2. **把缺口写成一句话的能力描述**，带上关键名词（例：「需要把 CSV 做透视汇总并出图」）。
   检索词就从这句话里抽，不要用「一个帮我处理数据的东西」这种描述去搜。
3. **按顺序试三个源**，第一个成功就停：
   - 内置清单（见下方来源表）
   - 本地已装但未启用的技能 → 提示用户开启，不要重装
   - 开源社区（GitHub 上的技能仓库）
4. **装完必须验证**，三件事：
   - 技能文件真的落到技能库里了吗（不是只下载了）
   - 技能名和描述是不是覆盖了那条能力描述里的关键名词
   - 是否真的有工具可用（方法论型技能只注入提示词，工具型才注册工具）
5. **回填给主持**：装了什么、装到哪个角色、覆盖哪条能力。
   没装成的，逐条写清原因，不许静默跳过。

## 自检清单

交付前逐条打勾，任何一条打不上就不算完成：

- [ ] 缺口描述里有关键名词，检索词是从它抽出来的，不是泛词
- [ ] 本地已启用技能已逐条比对过，没有重复安装
- [ ] 安装数量 ≤ 3，且每一个都直接服务于那个具体缺口
- [ ] 每个已装技能都验证过「真的在库里」和「名字覆盖关键名词」
- [ ] 失败项有真实原因（不是「没找到合适的」）
- [ ] 已把「装了什么 / 覆盖什么」回报给主持，不是静默完成

## 来源表（按需检索，不要全量扫）

- 方法论型（工作流 + 自检清单）：本套件自带的 14 个包
- 工具型（怎么调某个 API）：技能库页已有条目
- 开源社区：GitHub 上的技能仓库，注意区分「真技能」和「只有一段 README 的项目」

## 与 role-forge 的分工

装技能解决的是「缺一门手艺」。如果装完技能还是没人能接这单——
因为压根没人具备**判断**这件事的能力——那是造新角色（role-forge）的事，不要继续装技能。
