# 前端实现

> 与 `frontend-design`（工具型，讲怎么调 API）互补。这个包讲**怎么把界面做对**。

## 开工前必须先有的东西

没有下面这三条，不许开始写代码：

1. **设计规格**：主色/语义色/灰阶的 HEX、字号阶梯、间距刻度（见 `ui-design` 包）。
   没有规格就写代码 = 让随机数决定视觉。
2. **验收标准**：至少 3 条，写成能验证的句子（见 `review` 包的要求）。
   「好看」不是验收标准。
3. **数据形态**：这个页面拿到的数据长什么样？给一个真实样例（字段名 + 类型 + 空值情况）。

## 状态覆盖（最容易漏、最容易被骂）

**每一个**会发请求/读数据的组件，都必须有这 6 态，缺一个就算未完成：

| 状态 | 必须有 |
|---|---|
| 加载中 | 骨架屏或 spinner，不许是空白 |
| 空数据 | 一句说明 + 一个引导动作，不许是「暂无数据」四个字 |
| 请求失败 | 错误信息 + 重试按钮，**不许静默失败** |
| 部分成功 | 说明哪部分成功哪部分失败 |
| 权限不足 | 明确说「你没权限」，不要假装没这功能 |
| 超长内容 | 截断规则已定义（不是靠浏览器自己溢） |

## 数据形态先想清楚

- 列表页先问：**空的时候长什么样**（首屏空 / 搜索无结果 / 筛选后为空，这三种是不同状态）。
- 数字先问：**可能为空吗**（0 和 null 不是一回事，别用 `||` 把 0 变成 0 的假象）。
- 时间先问：**时区按谁算**（用户本地还是服务端）。
- 长文本先问：**截断还是换行**。

## 交互硬要求

❌ 不许没设计规格就动手写代码 —— 那等于让随机数决定视觉。
❌ 不许只做「加载中」这一态，缺另外五态就是未完成。
❌ 不许用 `||` 处理 null（0 会被吞成假象）。
❌ 不许说「应该能跑」就当跑过了，必须实测并贴控制台结果。


- 所有异步操作可取消（组件卸载后不许 setState）。
- 提交类按钮必须有 `disabled` 中间态，防重复提交。
- 表单校验在提交前，不在失焦时才第一次报。
- 键盘可达：焦点态可见，弹层能 Esc 关。

## 自检清单

- [ ] 设计规格已给出（HEX / 字号 px+行高 / 间距刻度）
- [ ] 验收标准 ≥3 条，且每条可验证
- [ ] 6 态全部实现（加载/空/失败/部分成功/无权限/超长）
- [ ] 三种空态已区分（首屏空 / 搜索无结果 / 筛选后为空）
- [ ] 数字未用 `||` 处理 null（0 正确显示）
- [ ] 异步可取消，无卸载后 setState 警告
- [ ] 提交按钮有 disabled 中间态
- [ ] 焦点态可见，弹层可 Esc 关闭
- [ ] 浏览器控制台 0 error
- [ ] 已实际跑过一遍（不是"应该能跑"）

## 交付时说清

实现了哪些状态、验收标准逐条对照结果、控制台有无错误。
「已完成」必须附实测结果。
