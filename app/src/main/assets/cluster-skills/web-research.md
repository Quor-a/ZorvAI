# 联网调研

## 🔴 铁律

❌ 不许凭训练记忆回答时效性问题。最新版本、最新价格、最新政策、谁在用 —— 一律要实际检索。
  记忆里的答案可能过期两年，且错得很有自信。
❌ 每条结论不挂来源。查不到就明说「未找到」，不许用记忆填空。
❌ 只拿 A/B 级来源当依据。C/D 级只能当线索，不许直接写进结论。
❌ 拿单个非权威来源当定论。交叉验证不足时必须标注未验证。

补充（为什么这么严）：时效性内容一旦记错，**错得很有自信**——
用户不会怀疑一个语气笃定的错误数字。所以一手源优先不是偏好，是止损。

## 来源分级

| 级别 | 类型 | 怎么用 |
|---|---|---|
| A | 官方文档、源码、原始公告、法规原文 | 可直接作为结论依据 |
| B | 官方博客、release notes、财报 | 可用，需标日期 |
| C | 技术社区（StackOverflow、论坛、issue） | 只作旁证，需交叉验证 |
| D | 个人博客、无出处文章、AI 生成内容 | **只作线索，不作依据** |

**至少 2 个独立来源，其中 1 个是 A/B 级**，才可写成结论。
只有一个 C/D 级来源时，明说「仅找到单一非权威来源，未交叉验证」。

## 检索策略

1. **先分解问题**：把大问题拆成 3~5 个子问题，每个子问题独立检索。
   一次大而全的检索什么都查不到。
2. **关键词先想好**：中英各准备一套（本项目技术调研常需英文源）。
3. **搜不到就换词**，不重复同义词空转。换维度：术语换说法、换官方站、换 issue 区。
4. **找到入口后追一手**：搜到一篇博客 → 顺着它引用的官方文档走，以官方文档为准。

## 工作流

1. 拆成 3~5 个子问题。
2. 逐个检索，记录每条结果的 URL + 来源级别 + 日期。
3. 每条结论回到一手源核实。
4. 交叉验证（≥2 独立源）。
5. 写报告：**结论 + 依据 + 不确定的地方**。

## 时效性处理

任何带时间属性的结论必须**标明信息时间**：

> ✅ 「截至 2026-10，该库最新版本为 x.y.z（来源：官方 release 页面）」
> ❌ 「最新版本是 x.y.z」

版本号、价格、政策、任职信息这类**变化极快**，额外要求：
- 给出查询日期
- 如果超过半年没验证，标注「可能已过期」

## 找不到时

**明说找不到，并给出已经试过什么。**

正确：
> 「没查到 x 的官方文档。试过：官网文档站搜索、GitHub 仓库、issue 搜索。没有直接说明，
> 需要你提供来源或确认现状。」

错误：
> 用记忆里的大概印象编一段，并加上「一般来说」「通常」。
> 或者只回一句「查不到」，让用户以为你没找。

## 自检清单

- [ ] 问题已拆成 3~5 个子问题
- [ ] 时效性内容已实际检索（非凭记忆）
- [ ] 每条结论挂了来源 URL
- [ ] 至少 2 个独立来源，其中 ≥1 个 A/B 级
- [ ] 一手源已核对（二手博客只作线索）
- [ ] 时间敏感结论标了信息日期
- [ ] 版本/价格/政策类未验证超半年的已标「可能已过期」
- [ ] 找不到的地方明说了，且列出了试过的途径
- [ ] **无「一般来说」「通常」式记忆填充**
- [ ] 区分了「查到的」与「推断的」

## 交付时说清

检索了哪几个来源、来源级别、结论哪些是交叉验证过的、哪些没查到。
**没查到的部分不许藏在正文里，要单独列出来。**
