# Markdown 文档

## 结构规则

1. **倒金字塔**：第一屏必须能独立看懂。结论 / 变更点 / 怎么用，放最前。
   读者可能只读前 20 行。
2. **标题不跳级**：`#` → `##` → `###`。不许从 `#` 直接跳到 `###`。
3. **一个 h2 一件事**。一个标题下塞三件事，读者就得通读。
4. **段落 ≤3 行**。超过就拆成列表或表格。

## 内容硬要求

- **代码块必须标语言**：```` ```kotlin ````、```` ```bash ````。
  无语言的高亮等于没有。
- **不许留占位符**：`TODO`、`待补充`、`xxx`、`...`（指代缺失内容）、
  `Lorem ipsum`、示例路径 `/path/to/your/file`（除非明确是占位说明）。
  出现了就补齐或删掉整段，不许留着。
- **命令必须能直接跑**：给出完整命令行（含必要参数），不是 `npm install` 后跟一句「然后配置一下」。
- **链接必须可达**，且用说明性文字（`见 [故障排查](troubleshoot.md#常见错误)`），
  不许裸 URL 堆在正文里。
- **表格用于对比**，不是用于排版。单元格超过 3 句话就别用表格。

## 数字与事实

❌ 不许留 `TODO` / `待补充` / `xxx` / `Lorem ipsum` / `/path/to/your/file` 这类占位。
❌ 不许写不带语言标记的代码块。
❌ 不许凭记忆写版本号 / 路径 / 数字 —— 不确定就标「待确认」，不要猜一个像样的数。


- 涉及版本、路径、命令的地方，**以仓库实际值为准**，不许凭记忆写。
  写之前先查（grep / 读文件）。
- 不确定的数字写「待确认」，**不要猜一个像样的数**。
  错的具体数字比明说不确定伤害大得多。

## 工作流

1. **先写第一屏**：结论 / 变更点 / 用法。
2. **列提纲**：所有 h2，确认没有跳级、没有重复。
3. **填内容**：逐节填，代码块当场标语言。
4. **搜占位符**：`grep -nE "TODO|待补充|xxx|\.\.\." 文件名`，逐个处理。
5. **自查链接**：每条链接点一遍（或至少确认文件存在）。

## 自检清单

- [ ] 第一屏能独立看懂（结论在前）
- [ ] 标题层级连续无跳级
- [ ] 所有代码块都标了语言
- [ ] `grep` 搜占位符结果为 0
- [ ] 所有命令含完整参数，可直接复制执行
- [ ] 无裸 URL，链接都有说明性锚文本
- [ ] 表格单元格均 ≤3 句
- [ ] 版本/路径/数字已实际查证过，不是凭记忆
- [ ] 不确定处标了「待确认」而非猜数字

## 交付时说清

文档路径、字数、搜过占位符（结果 0）、代码块数量。
