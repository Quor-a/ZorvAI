# 策略与决策

## 核心原则

**策略的价值在于排除了什么。**
只列「可以做 A 也可以做 B」的输出不是策略，是逃避决策。给出推荐，并写清代价。

## 强制结构

每次给策略必须包含这三段，缺一段就不算策略：

1. **事实**（与判断分开写）
   已核实的东西，每条能追到来源（实测/查仓库/查文档）。
2. **判断**（你的推断，明确标为判断）
   每条判断带一个**可证伪条件**：什么现象出现就说明这个判断错了。
3. **取舍**（推荐 + 放弃了什么）
   推荐哪条路 + **代价是什么** + 放弃了哪条路、为什么。

## 「可证伪条件」怎么写

❌ 不许只列「可以做 A 也可以做 B」—— 那是逃避决策，不是策略。
❌ 不许把事实和判断混在同一段里写。
❌ 不许用肯定句包装不确定（「大概」「应该」这类模糊限定词后面必须跟具体条件）。


这是判断质量的唯一标尺。写成这样：

> 判断：端侧用文本协议比原生 function calling 更稳。
> 可证伪：若在 1.5B 以下模型上，文本协议的「行动：」解析成功率 <60%，则此判断不成立，应改回原生工具调用。

写成这样（不合格）：

> 判断：端侧用文本协议更稳。（无法证伪，就是句感觉）

**判据：说不出「什么现象出现就说明我错了」→ 那不是判断，是意见。**

## 事实纪律

- 涉及本项目行为的陈述必须**实测/查证**，不许凭记忆。
  不确定的写「未核实」，不要用肯定句包装不确定。
- 不许编造外部数据（市场规模、竞品功能、用户量）。
- 「通常」「一般来说」这类模糊限定词后面必须跟一个具体条件。

## 决策维度（选型时至少覆盖）

| 维度 | 要回答 |
|---|---|
| 可行性 | 现在能做吗？缺什么？ |
| 代价 | 花了什么（时间/复杂度/维护成本）？ |
| 失败模式 | 最坏情况是什么？可逆吗？ |
| 验证成本 | 多大代价能验证这个选择对不对？ |
| 退出成本 | 选错了要付多少代价才能换回来？ |

**验证成本低而退出成本高的选择，先做小实验再全量。**

## 工作流

1. 分清哪些是事实、哪些是判断（**先分开写，别混在一起**）。
2. 核实所有事实（不核实的必须标「未核实」）。
3. 给每个判断配可证伪条件。
4. 列候选方案（≥2，包括「什么都不做」）。
5. 给推荐，写代价。
6. 说清放弃了什么。

## 自检清单

- [ ] 事实段与判断段**物理分开**，没混写
- [ ] 每条事实可追源，或已标「未核实」
- [ ] 每条判断都有可证伪条件
- [ ] 至少 2 个候选方案（含「什么都不做」）
- [ ] 有明确推荐，不是「都可以，看你」
- [ ] 写清了推荐的代价
- [ ] 写清了放弃了哪条路、为什么
- [ ] 覆盖了失败模式与退出成本
- [ ] 无编造数据，无「通常/一般来说」式模糊限定

## 交付时说清

推荐什么、代价是什么、判断的证伪条件分别是什么。
