# 界面自检评分（ZorvAI GenUI）

界面生成后**先自检再交付**。五维打分，每项 0~5 分，总分 **低于 18 分必须重做**。

---

## 维度一：布局（Layout）0~5

- [ ] 上下顺序符合阅读习惯（标题 → 主体 → 次要信息 → 操作）
- [ ] 同一层级的东西对齐方式一致（不要一会儿居中一会儿左对齐）
- [ ] 没有元素超出边界被裁掉
- [ ] Row 里的元素没有互相挤压
- [ ] 卡片宽度一致（同一列的卡片应该一样宽）

**扣分红线**：出现元素重叠 → 0 分；元素被裁 → 最多 2 分。

## 维度二：层次（Hierarchy）0~5

- [ ] 一眼能看出最重要的信息是什么
- [ ] 标题 / 正文 / 辅助文字的字号有明显区分（至少差 2sp）
- [ ] 重要操作（按钮）视觉上最突出
- [ ] 相关信息被放在一起（视觉分组）
- [ ] 层次靠**字号 + 字重 + 间距**表达，不靠乱加边框

**扣分红线**：所有文字一样大 → 最多 2 分。

## 维度三：配色（Color）0~5

- [ ] 一屏内强调色不超过 2 个
- [ ] 文字与底色对比度足够（浅底深字 / 深底浅字）
- [ ] 卡片底色风格统一（不要一张白一张灰）
- [ ] 语义色用对（成功=绿、警告=橙、错误=红）
- [ ] 没有出现高饱和撞色（如亮红配亮绿）

**扣分红线**：出现 3 个以上强调色 → 最多 2 分。

## 维度四：排版（Typography）0~5

- [ ] 没有文字被截断（"..." 或只显示半行）
- [ ] 没有文字竖排（一字一行）
- [ ] 中文字号 ≥ 12sp
- [ ] 长文本有合理换行，不是挤成一行
- [ ] 数字与单位在同一节点（`28°` 而非 `28` `°`）

**扣分红线**：出现文字竖排或叠印 → 0 分。

## 维度五：密度（Density）0~5

- [ ] 没有超过 32dp 的莫名空白
- [ ] 卡片内部下方没有大片留白
- [ ] 卡片之间间距 8~16dp
- [ ] 内容撑满一屏的合理比例（不要只占上半屏）
- [ ] 没有空卡片 / 空容器占位

**扣分红线**：出现大片说不清的空白 → 最多 2 分。

---

## 常见扣分项速查（对照修复）

| 症状 | 根因 | 修复 |
|---|---|---|
| 卡片下方一大块空 | 纵向写了 `height: "match"` 或塞了大 spacer | 删掉高度，让内容撑 |
| 文字一字一行竖着排 | Row 里文本没给宽度，被兄弟挤没了 | 给文本节点明确宽度，或改用 column |
| 文字笔画糊成一团 | 用了 `box`（叠加布局）放多个子节点 | 改用 `column` |
| 出现 `⚠ 未知组件` 的淡红卡 | 类型名写错 / 自造了名字 | 改用真实类型名，或 `column`+`text` 组合 |
| 元素被裁掉一半 | 固定宽度太大 + padding 叠加 | 去掉固定宽度，改用不写宽度 |
| 卡片一张白一张灰 | 底色没统一 | 统一用 `surface` 或统一透明 |
| 内容只占上半屏 | 有空节点在撑高度 | 找出并删掉空节点 |

---

## 执行方式

生成界面后在心里过一遍：**布局几分、层次几分、配色几分、排版几分、密度几分**。

- 总分 ≥ 22：可以交付
- 18~21：挑最低的那一项改一版再交付
- < 18：**重做**，不要拿半成品给用户

**最重要的三条**（占了实测翻车的七成）：
1. 纵向不许写 `height: "match"`
2. 要排列就用 `column`，`box` 是叠加
3. 类型名必须是真实存在的
