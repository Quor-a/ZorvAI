# 文案写作

## 动笔前先定两件事（不许跳过）

1. **写给谁**：具体到一个人（例：「刚做完第一版产品、正在找设计师的独立开发者」），
   不是「我们的用户」。
2. **读完之后他要做什么**：一句话，能被验证。
   读完要注册 / 要点那个按钮 / 要转发 —— 只能选一个。选不出说明这篇不该写。

## 🔴 禁止的 AI 腔清单

以下这些是训练数据里的高频套话，出现即删：

- ❌ 「在当今快速发展的时代」「随着……的不断发展」
- ❌ 「赋能」「抓手」「闭环」「链路」「颗粒度」「对齐一下」
- ❌ 「不仅……而且……」「让我们一起……」
- ❌ 每段都是「总-分-总」的三段式排比
- ❌ 空洞形容词连用：卓越的、创新的、全面的、极致的
- ❌ 「 solutions 」「一站式」「无缝」
- ❌ 结尾升华成人生感悟

## 替换规则：形容词 → 数字

| 别写 | 改成 |
|---|---|
| 速度很快 | 3 秒出结果 |
| 支持很多模型 | 支持 4 家：GPT / Claude / Qwen / DeepSeek |
| 界面很简洁 | 首页只有 1 个输入框 |
| 大量用户在使用 | 已有 2 万多人在用 |
| 兼容性好 | Windows / macOS / Linux 都能跑 |

**判据：一个形容词能不能换成数字或具体动作？换不了就删掉它。**

## 标题

- 不许标题党（「震惊」「必看」「终于」）。
- 标题必须包含**具体信息**（数字/对象/动作），不是主题概括。
  ✅「3 个设置让 MNN 在 1.2B 模型上不卡死」
  ❌「关于模型部署的一些优化」

## 事实纪律

- 不许编造数据、用户数、奖项、引用来源。
- 需要引用他人观点时给出来源名；不确定就不写。
- 涉及**本项目实际行为**的描述，必须以代码/实测为准，不许凭印象。
  写「已支持 X」之前先确认 X 真的存在。

## 工作流

1. 写目标句（读完要做什么）。
2. 列 3~5 个要点，每个要点必须有具体数字或具体动作。
3. 写标题（含具体信息）。
4. 成文，然后**朗读一遍**：读到需要换气的地方说明句子太长，拆。
5. 搜 AI 腔清单，逐项删。

## 自检清单

- [ ] 开头写了「写给谁」（具体到一个人）
- [ ] 目标句唯一且可验证
- [ ] 每个形容词都换成了数字或具体动作
- [ ] AI 腔清单逐项查过（赋能/闭环/抓手/随着……发展 等）
- [ ] 标题含具体信息，不是主题概括
- [ ] 无标题党词
- [ ] 所有数据有出处或已实测，无编造
- [ ] 无「在当今……时代」类开场
- [ ] 朗读过，没有需要换气才能读完的句子
