# 界面手艺规范（ZorvAI GenUI）

这份规范来自真机实测的翻车记录。**每条都对应一类肉眼可见的丑**，写界面前先过一遍。

---

## 一、尺寸语义：别乱用 `match`

`width` / `height` 只有三种写法，写错一个整个界面就散：

| 写法 | 含义 | 该用的场景 | 别用的场景 |
|---|---|---|---|
| 数字（如 `200`、`48`） | 固定尺寸 | 头像、图标、按钮、分隔线 | 文本容器（会截断内容） |
| `"match"` | **占满父容器剩余空间** | 卡片要占满整行宽；Row 里那一块要吃掉剩余宽度 | **多个兄弟同时写 match**（会互相挤） |
| 不写 | 包内容（wrap） | 文本、按钮、图标 | —— |

**死规矩**：
- **纵向 Column 里不要写 `height: "match"`**。高度是内容撑出来的，写了只会制造空白。
- **Row 里最多一个 `width: "match"`**，其余兄弟让它包内容。
- 卡片宽度**不要写数字**，不写（包内容 + 外层撑满）就是满宽。

## 二、容器选型：Box 是叠加，不是排列

| 类型 | 行为 | 用途 |
|---|---|---|
| `column` | **纵向排列** | 页面的主干、卡片内部 |
| `row` | **横向排列** | 一行内的左右分栏（图标+文字、头像+信息） |
| `box` / `stack` | **全部子项叠在同一位置** | 只有做叠放才用（角标、头像堆叠、背景上盖文字） |
| `container` | 纵向排列（多子项时） | 分组 |

**最容易犯的错**：想"把几个东西排一列"，却写了 `box` —— 结果是**所有文字叠在一起糊成一团**。要排列就用 `column`。

**死规矩**：只要子节点超过 1 个且你期望它们是一个接一个出现的，**必须**用 `column` 或 `row`。

## 三、密度：界面上不许有大片说不清的空白

空白只有两种合法理由：**分隔**（8/16/24dp）或**节奏留白**（内容块之间，最多 32dp）。

- 卡片内部：内容写完就结束，**不要靠 spacer 撑高**。
- 卡片之间：用 `spacing` 或 `spacer` 给 **8~16dp**，不要给 60dp 以上。
- **如果你算不准内容高度，就不要指定高度** —— 让内容撑。

反例（都是实测出现过的）：
```
❌ 卡片里写 {"type":"spacer","style":{"height":120}}   → 一大块空
❌ 卡片写 {"style":{"height":"match"}}                  → 卡片撑满剩余屏，下面全空
❌ 用了一个不存在的类型（如 spacer2）                    → 降级成占位的错误卡，也是空
```

## 四、文本：最容易变形的一类

- **Row 里放长文本要给宽度**：文本节点要么不写宽度，要么和兄弟节点明确分工。不给宽度的文本在 Row 里会被挤成**一个字一行竖着排**（实测「体感 29~32℃」竖排在屏幕右边缘就是这个原因）。
- **一行只放一个标题**：不要把两句话塞进同一个 `row`。
- 长文本用 `text`，**不要用 `row` 拼句子**。
- 数字/单位要在一个文本节点里写完（`"28°"` 而不是 `"28"` + `"°"` 两个节点）。

## 五、组件名必须是真实存在的

SDK 里有 **525 个**真实组件类型。写错名字 → 渲染成 `⚠ 未知组件: xxx` 的降级卡（淡红底），界面立刻脏掉。

**常见可用类型**（确认存在，放心用）：

```
布局：column  row  box  container  stack  card  scroll  spacer  divider  grid
文本：text  heading1~heading6  label  caption  body
按钮：button  icon_button  fab  chip
数据：progress  progress_bar  slider  badge  kpi_card  stat_card  info_card
列表：list_item  list  section
媒体：image  icon  avatar  carousel
表单：input  text_field  switch  checkbox  radio  dropdown
状态：empty_state  loading  skeleton  alert  banner  toast
图表：chart_bar  chart_line  chart_pie  sparkline
装饰：surface  divider  stepper  tabs  bottom_bar  top_bar
```

**不确定的类型宁可用 `column` + `text` 组合，也不要自造名字。**

## 六、禁止自造标记语言

不许写 `<row>`、`<text size="17">`、`<spacer height="16"/>` 这类标签。
GenUI 是 **JSON**，不是 XML/HTML。所有内容都在 `properties` / `style` 里。

```
❌ <row><text>你好</text></row>
✅ {"type":"row","children":[{"type":"text","properties":{"text":"你好"}}]}
```

## 七、配色与层次（写不好看的重灾区）

- **一屏最多 2 个强调色**，其余用中性色。别每个卡片一个颜色。
- 卡片底色要么全部用 `surface`，要么全部透明 —— 不要混。
- 层次靠**间距 + 字号 + 字重**区分，不靠加边框。
- 文字与底色的对比度要够：浅底用深色字，深底用浅色字。
- **不要给每个元素都加阴影**，只有浮层/卡片需要。

## 八、写完之后自检（必做）

生成后逐条对照，任何一条不过就重来：

1. 有没有纵向写了 `height: "match"` 的？（→ 制造空白）
2. 有没有 `box` 里放了多个需要排列的子节点？（→ 文字叠印）
3. Row 里有没有没给宽度的长文本？（→ 竖排）
4. 有没有超过 32dp 的空白/间距？（→ 空洞）
5. 有没有用了上面清单里没有的类型名？（→ 降级错误卡）
6. 一屏里的强调色是不是超过 2 个？（→ 花）
7. 内容是不是只占屏幕上半部分？（→ 说明有空节点撑着）

---

**一句话**：先想清楚"这一屏从上到下由哪几块组成"，用 `column` 串起来，每块内容写完就收，不指定高度，用真实类型名。做到这四点，界面不会丑。
